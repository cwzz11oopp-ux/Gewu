# 实验工作台可靠性与假设展示设计

## 目标

修复本地实验工作目录错误和研究计划未展示的问题；将候选假设改为最多五条、中文、无排序含义的并列展示；让实验设计区域根据模型计划动态展示，而不把指标或研究领域写死。

## 范围与非目标

- 本次包含本地实验配置校验、计划数据标准化、实验计划展示、候选假设的生成约束和卡片布局。
- 本次不实现假设推荐指数、排序、星级、Elo 或任何按生成/推荐先后的表达。
- 现有“新增假设”保留，但当候选已满五条时必须由用户显式选择一个候选进行替换；系统不静默删除候选。

## 根因与修复边界

### 本地工作目录

`LocalGpuExperimentProvider.run` 把 `EXPERIMENT_WORKDIR` 当作进程当前目录下的相对目录，并在目录不存在时直接抛出 `LOCAL_EXPERIMENT_WORKDIR_INVALID`。当前持久化配置为 `experiments`，而项目中没有该目录。配置测试仅校验本地 GPU 已启用，未校验工作目录。

本次将把本地目录解析为绝对路径，在保存与测试配置时检查：目录存在、目录可读、任务入口可在目录内解析。失败响应将带上配置值、解析后的路径和中文修复建议。计划的本地命令必须与工作目录保持同一相对基准，避免进入工作目录后再次使用 `experiments/train.py`。

### 研究计划

规划模型有时返回 `{ "plan": { ... } }`，而 UI 读取顶层字段，因而展示了等待文案。后端在产出计划 artifact 前须标准化该兼容层：只有在顶层缺少计划字段且嵌套 `plan` 是对象时才解包；保留 provider 元数据。前端只消费统一后的计划契约。

## 数据契约

计划 artifact 的稳定字段为：

- `objective`：实验目标或待验证主张；
- `hypotheses`：被用于设计的假设文本；
- `dataset`：数据集、划分和来源；
- `comparisons`：每项含基线、变量、控制条件；
- `evaluations`：每项含指标、方向、统计或判定方法；
- `procedure`：执行步骤和重复次数；
- `resources`：GPU、时间或其他资源约束；
- `risks`：前置条件、风险与缓解措施；
- `additional_sections`：以上字段无法覆盖的模型自定义设计项。

模型仍可提供兼容的旧字段（`methods`、`baselines`、`metrics`、`experiment_constraints`）；后端转换为上述展示模型。缺失字段以“未提供”显示，绝不伪造固定指标。

候选假设 artifact 的 `candidates` 为 0 到 5 条。每条包含中文 `claim`、`verifiability`、`novelty_basis`、`risks`，以及可选的用户分析。模型提示词要求只返回中文和不超过五条；后端同样裁剪和校验。不存在 `score`、`rank`、`created_order` 等展示字段。

## 界面设计

### 创建与自动研究流程

左侧“创建研究”仅将界面切换为新的未开始状态：清空 A 区输入、取消当前 Run 和报告，不调用创建 Run 接口。A 区底部提供“开始研究”按钮；研究问题为空时不可用。点击后，前端创建 Run，并按顺序调用已有步骤接口：问题理解、文献检索、假设生成、证据推理。

证据推理完成后，前端必须停止自动队列并显示“等待选择假设”。用户确认假设后，前端继续顺序调用研究计划、实验任务、实验运行与分析、反馈修正、报告导出。每个请求完成并更新 Run 后才允许下一个请求开始；任何请求失败都停止队列并显示后端错误。

自动控制状态仅存在于前端页面。刷新或关闭页面不会取消已提交的当前后端请求，但不会提交后续请求；重新打开页面后，用户可依据已有 artifact 重新点击开始运行以继续。暂停为安全暂停：点击后显示“将在当前步骤结束后暂停”，当前请求完成后不再调度下一步，不强行中断 LLM 调用或真实 GPU 实验。

科研工作流顶部提供一个全局自动控制按钮，不再把每个步骤的播放图标作为自动运行入口：未运行或暂停时显示播放图标和“开始运行”，自动执行中显示暂停图标和“暂停运行”。时间线仍显示各步骤状态与重跑操作，但不暗示自动队列可并行执行。

### 候选假设

候选采用双列自适应卡片，在窄屏时单列。卡片没有 H 编号、时间、星级、分数或“推荐”标签；所有卡片视觉权重相同。卡片显示假设陈述、验证方式、风险及“用于实验设计”复选框。长文本默认摘要并支持展开/收起全文，数组内容以短列表显示。候选满五条时，“新增假设”进入替换选择流程，替换操作明确提示目标卡片。

### 实验设计

实验计划为可读的实验蓝图：目标、假设、数据、对比、评估、流程、资源、风险和补充设计项。每一段仅在模型提供数据时显示。评估项以动态表格显示，字段由模型提供，不固定为准确率、幻觉率或奖励。未知自定义项显示为标签和值的列表。长内容可折叠，容器允许换行且不超出卡片。

## 错误处理与可追溯性

- 工作目录失败必须保持错误代码 `LOCAL_EXPERIMENT_WORKDIR_INVALID`，并附加结构化诊断信息。
- 计划标准化需记录是否发生解包，便于在 agent trace 中追溯模型原始结构与标准化结果。
- 因候选数量超限发生的用户新增请求，必须返回明确的“请先选择替换目标”错误，不得悄悄丢弃输入。

## 验收与测试

- 不存在的本地目录在配置测试时失败，并返回解析路径；有效目录通过。
- 本地命令在工作目录中解析到正确入口。
- 嵌套计划和顶层计划都生成相同的规范计划；D 区显示实际模型内容。
- 模型返回超过五条候选时，artifact 最多保存五条；中文提示词可由 provider 测试验证。
- 假设区不渲染序号、分数、星级、排名或时间；中文长文本不会溢出，在桌面双列和窄屏单列都可展开阅读。
- 候选满五条时不能无提示新增第六条。
- 创建研究不创建后端 Run；开始研究创建一个 Run 并依次完成前四个步骤，然后停在假设选择处。
- 用户确认假设后，前端按顺序自动完成剩余步骤；暂停只能阻止下一步启动，页面关闭后不会继续自动调度。
