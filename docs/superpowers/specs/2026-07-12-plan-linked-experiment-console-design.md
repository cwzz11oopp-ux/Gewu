# 计划联动实验控制台设计

## 目标

修复候选假设卡片在桌面窄主栏中的横向溢出，并让实验执行区从已生成的实验设计中读取评估指标。运行前、运行中和运行完成后均围绕同一套评估定义显示信息，不再展示与本次计划无关的固定指标或示例曲线。

## 范围

- 候选假设区占主工作区的整行；桌面端最多两列、窄屏单列，不产生水平滚动或裁切。
- 实验设计与实验执行依次占主工作区整行；设计卡片保持完整阅读宽度，执行卡片紧随其后。
- 执行区从最新的 `plan.evaluations` 和 `experiment_result.metrics` 组合出指标表。
- 每一行显示：指标、方向、判定方式，以及可用时的实际结果。
- 没有计划时显示等待实验设计；计划存在但尚无结果时显示计划的评估指标与“待运行”；结果存在但计划中未声明该指标时，仍显示该结果并标记为“结果输出”。
- 只有结果里确实存在数值型时间序列时才显示趋势图；否则显示简洁的“本次任务未提供趋势数据”提示。

## 非目标

- 不改变后端实验运行、计划生成、指标命名或统计计算逻辑。
- 不猜测、补充或硬编码任意领域的指标、阈值、单位和曲线。
- 不为卡片的长内容增加展开/收起交互；本次通过整行布局、最小宽度约束和自然换行解决可读性。

## 数据契约

输入来自已有 artifact：

- `plan.content.evaluations`：数组。每项为对象；`metric` 是指标名，`direction` 是期望方向，`method` 是判定或统计方式。其余字段保留为展示补充信息。
- `experiment_result.content.metrics`：对象。键是运行输出的指标名，值是最终值或序列。

前端纯函数 `buildExperimentMetricRows(plan, resultMetrics)` 返回稳定行模型：

```ts
type ExperimentMetricRow = {
  key: string;
  label: string;
  direction: string;
  criterion: string;
  result: string;
  source: "plan" | "result";
};
```

计划指标优先按计划顺序输出；名称相同的结果填入对应行。其后追加未在计划中出现的结果键。空、错误类型或无效的评估输入不会导致渲染失败。

`findMetricSeries(resultMetrics)` 只接受数组中至少两个有限数值的指标并返回第一条；其他结果类型均不形成图表。

## 布局与状态

主网格桌面端仍有两列用于 A/B 内容，但 C、D、E 均跨两列：

```text
A 研究主题            B 文献
C 候选假设（全宽，两列卡片）
D 实验设计（全宽）
E 实验执行（全宽，日志与计划指标）
```

候选卡片内部使用 `minmax(0, 1fr)`，并保留 `min-width: 0` 和 `overflow-wrap: anywhere`。小于 960px 时所有内容变为单列。

执行区状态按可用 artifact 决定：

1. 没有计划：等待实验设计。
2. 有计划、没有任务：等待实验任务。
3. 有任务、没有结果：任务已生成，表格展示计划指标及“待运行”。
4. 有结果：表格展示计划指标与运行结果，并视真实序列决定是否绘图。

## 验收标准

- 候选假设、实验设计和实验执行均在 `.workspace-grid` 中跨两列；候选网格的列定义不含固定 `240px` 最小宽度。
- `buildExperimentMetricRows` 能保留计划顺序、合并同名结果、追加未声明结果，并为缺失值给出中文回退文本。
- 执行器不再包含固定 SVG 坐标点，也不硬编码 `accuracy`、`hallucination_rate` 或 `reward`。
- 结果无数值序列时不渲染 SVG；有至少两个有限数值的序列时显示由该序列形成的 SVG。
- 前端契约测试、展示工具测试和 TypeScript/Vite 构建均通过。
