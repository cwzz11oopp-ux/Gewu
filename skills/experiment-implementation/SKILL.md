# Experiment Implementation

Use the configured Qwen Provider to generate the scientific implementation for one provider-neutral `ExperimentBundle`. The system compiles the accepted Plan, Task, frozen contract, dataset binding, seeds, parameters, identifiers, output locations, and smoke/full mode into a deterministic runtime contract and Harness.

## Code contract

- **Mandatory runtime scaffold:** import the system-provided scaffold `import gewu_runtime as gr` and drive every protocol surface through it. `args = gr.get_args()` parses `--run-id`, `--experiment-id`, `--result-id`, `--output`, `--seed`, and `--smoke-test`, and injects every frozen Plan parameter as an attribute, so `args.batch_size` is always defined even if your code never declared it. `gr.epoch_budget()` returns the system-bound epoch count (always 1 during smoke), `gr.is_smoke()` is the stage branch, `gr.data_root()` is the verified dataset root, and `gr.write_result(metrics, epoch_metrics=..., primary_prefix=...)` normalizes and persists the per-seed result under the system contract. Pass the intervention-variant metric prefix (for example `"ECA_"`) as `primary_prefix` so the manifest's aggregate `expected_metrics` keys are completed deterministically from the intervention variant. Never hand-roll argparse for the protocol flags, never serialize the result JSON yourself, and never list `gewu_runtime` in `requirements` — the Harness provides it next to `train.py`.
- **Mandatory pre-return check:** detach every PyTorch tensor before converting it to NumPy. Safe equivalent forms are allowed, including `tensor.detach().cpu().numpy()` and a detached temporary moved to CPU before `.numpy()`; never convert a live/autograd tensor directly.
- Return exactly one `{ "path": "train.py", "content_lines": [...] }` item. Put exactly one physical Python line in each string, using an empty string for a blank line. Never return a `content` field, embedded newline characters, literal `\n`, Markdown fences, fragments, ellipses, or explanations.
- Do not return `entrypoint`, identifiers, output paths, or `python_args`; the backend/Harness adds those protocol fields deterministically.
- Make every Python file syntactically valid under `compile(source, path, "exec")`.
- Build a `metrics` dict whose values are all single finite numbers (flatten comparison outputs into distinct metric keys; nested metric objects and boolean values are invalid; keys may be constructed dynamically), plus an `epoch_metrics` list `[{"epoch": 1, "<metric-key>": <finite number>, ...}, ...]` with strictly increasing one-based integer `epoch` values recording every evaluated metric at that epoch end as native finite numbers. Pass both to `gr.write_result(metrics, epoch_metrics, primary_prefix=<intervention prefix>)`; the scaffold writes the finite result JSON at the runtime-provided output path and carries identity fields and the seed. The system records the per-epoch array as observational training history; the scalar `metrics` object remains the scientific contract. The system Harness owns the final result envelope, identifiers, and final output location.
- For a baseline-versus-intervention experiment, train and evaluate both variants but call `gr.write_result` exactly once, after both complete. Keep each scalar result under unambiguous `Baseline_` and intervention-prefixed keys, and copy intervention values to the exact required aggregate keys. Never call `gr.write_result` inside a per-variant helper: it writes one per-seed output path and a later variant would overwrite the baseline evidence.
- `--seed` is the authoritative runtime seed. Use `args.seed` from `gr.get_args()` to initialize every random source actually used by `train.py` (such as `random`, `numpy`, and `torch`), and use that same value for baseline, variant, training, validation, and result output. The result JSON `seed` equals `args.seed` (the scaffold writes it); never hard-code a seed or select one from Plan seeds inside `train.py`.
- Smoke mode must load the complete verified dataset and execute the exact same split, preprocessing, labels/targets, and validation code as later stages. Never subset, sample, rebalance, reduce classes/anomalies, or create a smoke-only split. Use the Harness-selected one seed and stop only after one real train batch and one real validation/evaluation batch, including prediction and metric calculation. Use `gr.is_smoke()` and `gr.epoch_budget()` for the system-bound stage budget (smoke is always one seed, one epoch). For IPIX17, load `DATA_ROOT/IPIX17/clutter.mat` and `DATA_ROOT/IPIX17/mubiao.mat`, construct complete `X/y` in clutter-to-target order, and keep `stratify=y` for the shared classification split. If the shared frozen split has fewer than two train classes, raise a clear data error; when repairing `The number of classes has to be greater than one`, fix shared split/label handling rather than adding a smoke subset.
- Declare every third-party import in `requirements`. Do not assume dependencies are installed, install packages, download datasets at runtime, or execute the bundle in this step.

## Experiment contract

- Implement the accepted plan exactly. Use the runtime-provided `DATA_ROOT` and dataset card without silently substituting another dataset or hard-coding a dataset root. Never download data at runtime.
- If the verified local Fashion-MNIST contract lists `train-images-idx3-ubyte.gz`, `train-labels-idx1-ubyte.gz`, `t10k-images-idx3-ubyte.gz`, and `t10k-labels-idx1-ubyte.gz` directly under `DATA_ROOT`, implement a local gzip IDX reader over exactly those files. Do not use `torchvision.datasets.FashionMNIST`, which expects a different `FashionMNIST/raw` cache layout; do not create, copy, move, or download data to imitate that layout.
- For Fashion-MNIST, the user-facing target trio T-shirt/top, Coat, Shirt maps exactly to labels `0`, `4`, `6`. Compute the three symmetric confusion pairs `(0, 6)`, `(6, 4)`, and `(0, 4)`; never substitute label `1` (Trouser) or `2` (Pullover) for Shirt.
- Implement a real experimental intervention. Baseline and variant must differ only in the factor under test; never construct and train identical baseline and "improved" models under different variable names.
- Match model input shape, class count, preprocessing, metrics, repetition count, seeds, and every Plan parameter to the accepted Plan. The Bundle manifest must echo the Plan's exact `seeds`, `parameters`, and expected metrics; schema examples such as `[42]` or `{}` are never defaults. Read system-bound seeds and parameters from the Harness environment when needed; do not redefine frozen values.
- When GPU is required, check CUDA availability, move the model and tensors to the CUDA device, and synchronize before recording results.

Before returning, inspect the complete bundle against every item above. Return only the JSON bundle.

## Harness gates

- Use documented APIs from the declared dependency versions. Prefer `torch.nn.functional` for functional activations such as `softplus`; do not invent top-level framework functions.
- Keep executable work inside `main()` so importing or compiling the module does not start training.
- Make model construction and one forward/loss/backward/update batch valid before the full experiment is eligible to run.
- Before converting any PyTorch tensor to NumPy, detach it first. `tensor.detach().cpu().numpy()` and equivalent detached temporary forms are valid; direct `.cpu().numpy()` on a live/autograd tensor is forbidden.
- For every epoch-based training loop, emit exactly one JSON line at epoch end with `event: "epoch_end"`, `variant`, `seed`, one-based `epoch`, `total_epochs`, and mean `loss`; call `print(..., flush=True)` so the harness can observe real progress. Populate the `epoch_metrics` array with the same per-epoch values so the persisted result carries the training curve. Emit `variant_start`, `seed_start`, and `variant_end` JSON events when those dimensions exist. Do not rely on tqdm-only terminal rendering.
- Treat the accepted Plan's `parameters.epochs` as a model-authored formal budget. For a genuinely epoch-trained model, carry optimizer/model state forward across epochs. For non-epoch estimators such as scikit-learn `LogisticRegression`, train once with the separately planned `max_iter` (or the estimator's equivalent) and report one observational epoch; never implement the epoch budget as repeated independent calls to a converged `fit()` and never duplicate an unchanged final metric across fabricated epoch rows.
- When repairing an existing Bundle, make the smallest safe source change required by the supplied traceback. Preserve the accepted manifest dataset, parameters, seeds, expected metrics, identifiers, and GPU requirement exactly.
- For sequence likelihoods, distribution parameters and samples must retain identical batch, sequence, and feature dimensions (for example `[B, T, C]`). Do not squeeze a singleton feature dimension from Normal or Student-t location/scale tensors when the input remains `[B, T, 1]`.
- Give each sequence model one explicit input-shaping boundary. If `forward()` expands a batch of sequences from `[B, T]` to `[B, T, 1]`, callers such as scoring and validation must pass `[B, T]` rather than expanding it again; LSTM inputs must be 2D or 3D, never 4D.
- Evaluate complete validation and test sets in bounded DataLoader-style batches. Never call `x.to(device)` followed by a model invocation when `x` is the whole validation/test tensor; loop over fixed-size slices or a DataLoader, move only each batch to GPU, and concatenate the CPU scores so every verified example remains included without exhausting GPU memory.
- Before writing a result JSON, convert NumPy/PyTorch scalar values and arrays in nested metrics, histories, and diagnostics to native Python numbers and lists; `json.dump` must never receive tensor or NumPy scalar objects.
- Emit every `expected_metrics` entry from the accepted manifest as an exact, finite scalar key in both Smoke and full modes. Metric dictionaries cannot represent a vector by repeatedly assigning the same key: for a per-dimension diagnostic, set that required key once to an explicit aggregate such as the mean, and additionally emit each component using distinct dimension-suffixed scalar keys. Every metric label must name the score and model/variant it actually uses—do not label a reconstruction score from one variant as another variant's baseline or ablation result.
- Do not use version-specific NumPy warning aliases such as `np.ComplexWarning`; warning handling must remain compatible with the installed NumPy version or be omitted when it is nonessential.
- Treat every validator rejection as actionable repair feedback. Return another complete corrected source file rather than explanations or a weakened contract.

## Ownership boundary

You own only scientific implementation: model, loss, optimizer, data processing, training, evaluation, and the metrics values. The system owns deterministic runtime protocol: dataset root/identity, frozen seeds and parameters, run/task/result identity, CUDA/runtime context, smoke/full invocation, output destination, and final result envelope. Do not attempt to rewrite, replace, or bypass any system-owned protocol field during generation or repair.
